# مكتبة القارئ

نظام ويب كامل لبرنامج قراءة واستماع شبابي يمتد قرابة 20 أسبوعًا. مبني بـ Node.js + Express + EJS + SQLite.

## المزايا المنفذة

- تسجيل دخول بثلاث صلاحيات: مشارك، مشرف، مدير.
- لوحة مشارك متجاوبة للجوال تعرض الرتبة، الرصيد، إجمالي الرحلة، تقدم الأسبوع، النشاطات والإشعارات.
- إرسال إنجاز قراءة أو استماع مع انتظار اعتماد المشرف.
- اعتماد/رفض الإنجاز مع إضافة الدقائق داخل معاملة قاعدة بيانات واحدة.
- فصل `lifetime_minutes` عن `wallet_minutes`: الرتبة لا تنخفض عند شراء مكافأة.
- سجل معاملات كامل قبل/بعد لكل تغيير في الرصيد.
- نظام رتب قابل للتعديل من لوحة الإدارة.
- 20 أسبوعًا قابلة للتعديل والفتح/الإغلاق.
- متجر مكافآت: سعر، كمية، رتبة دنيا، مدة عرض، حد شراء.
- شراء آمن يتحقق من الرصيد والكمية والرتبة والحد، ثم يخصم الرصيد ويصدر قسيمة فريدة.
- قسائم بحالات: غير مستخدمة، مستخدمة، منتهية، ملغاة، ومنع الاستخدام المتكرر.
- لوحة متميزين قابلة للتشغيل/الإيقاف.
- إضافة مشاركين وتعطيلهم وإجراء تعديلات يدوية على الرصيد مع سبب إلزامي ومسجل.
- إعداد اختياري لاعتماد الإنجازات تلقائيًا بدل اعتماد المشرف.
- واجهة عربية RTL وهوية بصرية مستوحاة من المكتبات والرفوف وأجواء القراءة.

## التشغيل

يتطلب Node.js 22.13 أو أحدث.

```bash
npm install
npm start
```

ثم افتح:

`http://localhost:3000`

## ملاحظات النشر

- قاعدة البيانات الافتراضية SQLite ومناسبة لبرنامج صغير/متوسط على خادم واحد.
- عند التوسع الكبير يمكن نقل طبقة البيانات إلى PostgreSQL مع الحفاظ على نفس المنطق.
- استخدم HTTPS في الإنتاج.
- أنشئ نسخًا احتياطية دورية من `data/reader-library.db`.
- يفضل إضافة حماية CSRF ومحدد معدل محاولات الدخول قبل فتح النظام للعامة على الإنترنت.

## منطق الرصيد

هناك رقمان مقصودان:

1. `lifetime_minutes`: إجمالي الدقائق المعتمدة طوال الرحلة، ومنها تُحسب الرتبة.
2. `wallet_minutes`: الرصيد المتاح للشراء، ويقل عند الاستبدال.

هذا يمنع هبوط رتبة المشارك فقط لأنه اشترى مكافأة.


## النشر على Railway

هذه النسخة مجهزة للنشر على Railway بملف `Dockerfile` و`railway.json`. راجع `DEPLOY-RAILWAY.md` للخطوات. عند استخدام SQLite على الاستضافة يجب ربط Volume دائم بالمسار `/data` وضبط `DB_PATH=/data/reader-library.db`.

## التشغيل على الشبكة المحلية في ويندوز

السيرفر يستمع افتراضيًا على `0.0.0.0` عبر المتغير `HOST`، لذلك بعد التشغيل يمكن فتحه من نفس الجهاز عبر:

- `http://localhost:3000`

ومن الأجهزة المتصلة بنفس شبكة Wi‑Fi عبر عنوان IPv4 للجهاز، مثال:

- `http://192.168.8.169:3000`

يمكن ضبط المنفذ والعنوان في ملف `.env` أو متغيرات البيئة:

```env
HOST=0.0.0.0
PORT=3000
SESSION_SECRET=ضع-هنا-قيمة-طويلة-وعشوائية
INITIAL_PASSWORD=Maktaba#2026
```

> ملاحظة: المشروع لا يحمّل `.env` تلقائيًا حاليًا لعدم وجود dotenv. على ويندوز يمكن ضبط المتغيرات قبل `npm start`، أو تشغيل الإعدادات الافتراضية محليًا. عند النشر الفعلي يجب تعيين `SESSION_SECRET` من منصة الاستضافة.

### جدار حماية ويندوز

افتح PowerShell كمسؤول ثم نفّذ مرة واحدة فقط:

```powershell
New-NetFirewallRule -DisplayName "Maktabat Al-Qari Port 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private
```

للتحقق من وجود القاعدة:

```powershell
Get-NetFirewallRule -DisplayName "Maktabat Al-Qari Port 3000"
```

ولحذفها لاحقًا:

```powershell
Remove-NetFirewallRule -DisplayName "Maktabat Al-Qari Port 3000"
```

يفضل أن تكون شبكة Wi‑Fi في ويندوز مضبوطة كشبكة **Private**، ولا ينصح بفتح المنفذ على شبكة عامة.

### فحص سريع

1. شغّل `npm install`.
2. شغّل `npm start`.
3. افتح `http://localhost:3000` من الكمبيوتر نفسه.
4. من الجوال المتصل بنفس الواي فاي افتح `http://192.168.8.169:3000`.
5. إذا تغير IPv4 لاحقًا استخدم `ipconfig` لمعرفة العنوان الجديد.
